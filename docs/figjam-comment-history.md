# BUVI FigJam 코멘트 이력 및 구현 대조표

> 대상: `BUVI 어르신 건강 지킴이 - 설문` FigJam의 화면별 코멘트 스레드
>
> 목적: 디자인 피드백의 의도, 현재 반영 상태, 후속 결정 사항을 한 곳에서 추적한다.
>
> 기준일: 2026-08-14

## 상태 표기

| 상태 | 의미 |
| --- | --- |
| 반영 확인 | 현재 `public/buvi.html`에서 동작 또는 문구를 확인한 항목 |
| 부분 반영 | 핵심 UI는 있으나 실제 데이터·연동 또는 세부 규칙이 남은 항목 |
| 결정 필요 | 제품 정책, 외부 연동, 의료적 검증처럼 구현 전에 합의가 필요한 항목 |
| 후속 점검 | 기능은 반영됐지만 실제 기기·브라우저에서 재확인이 필요한 항목 |

## 1. 전역 디자인·접근성 원칙

### 1-1. 큰 글씨와 글자 크기 조절

- 모든 핵심 화면에서 어르신이 읽기 쉬운 크기와 굵기를 사용하고, 제목·본문·보조 문구의 위계를 명확히 유지한다.
- 헤더의 글자 크기 제어는 작은 화면에서 버튼이 넘치지 않도록 커스텀 드롭다운으로 전환한다.
- 드롭다운은 시스템 기본 UI가 아니라 현재 선택값, 펼침 상태, 체크 상태가 보이는 디자인 UI를 사용한다.
- 425px 이하에서는 로고 텍스트가 불필요하게 축소되거나 줄바꿈되지 않아야 한다.
- 1024px 폭은 데스크톱이 아니라 태블릿 레이아웃으로 처리한다.

**상태: 반영 확인 / 후속 점검**

- 글자 크기 배율, 커스텀 선택 UI 및 화면 폭별 헤더 전환 로직이 존재한다.
- 실제 iOS Safari, Android Chrome, 데스크톱 Chrome에서 드롭다운 펼침·닫힘과 포커스 이동은 재점검한다.

### 1-2. 공통 반응형 안정성

- 가로 스크롤은 어떤 해상도에서도 발생하지 않아야 한다.
- 고정 헤더·하단 내비게이션이 콘텐츠, 설문 버튼, 로그인 버튼을 가리지 않아야 한다.
- 긴 콘텐츠는 문서 전체가 한 번에 세로 스크롤되고, 중첩 스크롤을 만들지 않는다.
- 데스크톱의 콘텐츠 배경, 그림자, 회색 여백은 태블릿과 다른 표현이 필요할 때만 사용한다.
- 낮은 세로 높이의 데스크톱에서도 홈·설문·결과의 마지막 콘텐츠가 하단 내비게이션 아래로 숨지 않아야 한다.

**상태: 부분 반영 / 후속 점검**

- 공통 `overflow-x` 방지와 폭별 레이아웃 보정은 반영되어 있다.
- 화면별 실제 전체 스크린샷(1920×1080, 1024×768, 375×667)으로 회귀 점검이 계속 필요하다.

### 1-3. 카드와 경계선 체계

- `#F3F4F6` 계열의 정보 박스는 필요 이상의 외곽선과 그림자를 사용하지 않는다.
- 결과·도움말처럼 그룹을 구분해야 하는 경우에는 강한 테두리 대신 도움말과 같은 연한 1px 실선을 사용한다.
- 회색 그룹 배경 안의 세부 콘텐츠는 흰색으로 두어 정보 위계를 만든다.
- 선택되지 않은 아이콘은 line, 선택된 아이콘은 fill 스타일로 구분한다.

**상태: 반영 확인 / 후속 점검**

- 키패드는 회색 컨테이너+흰색 버튼으로 통일되어 있다.
- 결과·도움말의 실선 농도는 화면별 최종 시안과 육안 비교가 필요하다.

## 2. 로그인 전 화면

### 2-1. 데스크톱 로그인 레이아웃

- 로그인 전에는 좌측 노란 로그인 히어로와 우측 BUVI 소개 영역을 유지한다.
- 좌측 로그인 폼의 아이디·비밀번호·자동 로그인·로그인/찾기 버튼은 세로 높이가 낮아져도 잘리지 않아야 한다.
- 노란 히어로의 제목, 본문, 말풍선, 캐릭터는 작은 데스크톱에서도 서로 겹치거나 넘치지 않아야 한다.
- 캐릭터 그림자는 전체 이미지에 적용된 필터처럼 보이지 않고 발밑에 자연스럽게 닿아야 한다.

**상태: 부분 반영 / 후속 점검**

- 반응형 배치와 로그인 폼 표시가 구현되어 있다.
- 낮은 높이의 데스크톱에서 로그인 버튼과 찾기 버튼이 모두 보이는지 재확인이 필요하다.

### 2-2. BUVI 소개 문구와 4행 구조

- 소개 제목은 “어르신 건강 지킴이, BUVI 입니다” 계열 카피를 사용한다.
- BUVI 약속 문구에는 `Beholding`, `Understanding`, `Vitality`, `Independence`의 의미가 포함되어야 한다.
- 소개 카드 4개는 바라봅니다·이해합니다·안내합니다·곁을 지킵니다의 순서를 유지한다.
- 각 카드의 캐릭터 영역 좌측에 구분선을 두어 4행 구조를 명확히 한다.
- 카드 제목과 설명의 행간을 압축하고 좌측 소형 캐릭터는 기존 대비 키운다.

**상태: 반영 확인**

- 약속 문구에 Independence가 포함되어 있고, 소개 카드의 텍스트·캐릭터 구성이 반영되어 있다.

## 3. 로그인 후 홈

### 3-1. 설문 전 기본 홈

- 로그인 직후에는 이전 사용자의 완료 결과를 자동 노출하지 않는다.
- 기본 홈은 노란 인사 히어로와 설문·상담·건강정보 3열 카드로 구성한다.
- 설문 전에는 상담 카드가 비활성 상태로 보이고, 결과가 있어야 상담을 시작할 수 있다.
- 3열 카드는 화면 높이에 따라 세로 공간을 과도하게 남기지 않고 하단 내비게이션과 적절한 간격을 유지한다.

**상태: 반영 확인 / 후속 점검**

- 로그인 성공 시 `resultViewed`를 초기화하고 기본 홈을 표시한다.
- 결과 존재 여부에 따라 결과 전용 요약과 상담 접근 상태를 전환한다.

### 3-2. 설문 완료 후 홈 요약

- 완료 후에는 “최근 설문 결과”를 간결한 요약으로 표시한다.
- 전체 결과 버튼은 “설문 결과 확인하기”처럼 목적이 명확한 문구를 사용한다.
- 요약에는 현재 위험도, 정상/위험 상태, 짧은 안내 문구만 우선 노출한다.
- 상세 기여도, 영역별 차트 등은 결과 화면으로 이동한 뒤 확인하도록 하여 홈을 복잡하게 만들지 않는다.

**상태: 반영 확인**

- 완료 여부에 따라 홈 위험 요약이 생성되며, 상세 차트는 결과 화면에서 관리한다.

## 4. 설문 공통 흐름

### 4-1. 한 화면 한 질문

- 한 화면에는 하나의 핵심 질문만 둔다.
- 질문 제목은 1~2줄 이내의 큰 글씨로 표시한다.
- 보조 설명, 예시, 태그는 질문을 방해하지 않도록 별도의 안내 영역 또는 접을 수 있는 안내로 둔다.
- 예/아니오, 성별 등은 넓은 대형 카드형 선택지와 명확한 선택 테두리·배경 피드백을 사용한다.

**상태: 반영 확인**

- 24문항의 질문별 렌더링과 선택형 카드 UI가 구현되어 있다.

### 4-2. 진행·이전·다음 동작

- 진행률은 전체 문항 수 기준으로 표기한다.
- 이전 질문과 다음 질문 버튼은 문항 콘텐츠의 실제 하단에 배치한다.
- 짧은 문항은 화면 세로 공간을 균형 있게 분배해 버튼이 하단 내비게이션 바로 위에 자연스럽게 위치하게 한다.
- 긴 문항은 모든 콘텐츠 다음에 버튼이 위치해야 한다.
- 다음 질문 이동 후에는 새 문항의 최상단으로 자동 이동한다.

**상태: 반영 확인 / 후속 점검**

- 다음·이전 이동 후 설문 스크롤을 상단으로 초기화하는 로직이 있다.
- 브라우저 주소창이 줄어드는 모바일 환경과 FHD 낮은 높이에서 최종 검증이 필요하다.

### 4-3. 수치 입력 공통 규칙

- `+/-`를 사용하는 수치 문항에는 직접 입력용 화면 내 숫자 키패드를 함께 제공한다.
- 키패드 UI는 회색 배경 컨테이너와 흰색 버튼 형태로 통일한다.
- 전체 삭제·지우기·소수점 등 보조 버튼은 숫자 버튼과 대비되되, 버튼 크기와 터치 영역은 동일한 체계를 사용한다.
- 가능한 경우 자동 포커스 이동과 값 검증을 제공한다.

**상태: 반영 확인**

- 연령, BMI, 다약제, 신체활동 시간, 앉아서 보낸 시간, TUG 직접 입력 키패드가 현재 구현에 있다.

## 5. 설문 단계별 상세 요구

### 5-1. 1단계 성별

- 능동적·주도적인 시니어 일러스트를 사용한다.
- 일러스트는 카드 안에서 잘리지 않아야 하며, 남성·여성 선택 상태가 색상만이 아니라 테두리와 배경으로도 명확해야 한다.

**상태: 반영 확인**

### 5-2. 2단계 연령

- 연→월→일 순서의 단계 입력과 화면 내 숫자 키패드를 제공한다.
- 직접 입력과 단계 이동을 모두 지원한다.
- 과거 “만 65세 이상만 허용” 안내와 입력 제한은 제거한다. 65세 이하도 입력할 수 있어야 한다.

**상태: 반영 확인**

- 현재 연령 입력은 키패드·단계 이동을 지원하며, 설문 참여 65세 제한 문구 및 제한 로직은 적용하지 않는다.

### 5-3. 3단계 체질량지수

- 키·체중은 `+/-`와 키패드 입력을 함께 제공한다.
- BMI는 자동 계산한다.
- 하단 안내 라벨은 “BMI” 단독 표기 대신 “체질량지수(BMI)”로 표시한다.

**상태: 반영 확인**

### 5-4. 4단계 복용약물

- 다약제 복용 여부와 약 개수 입력을 제공한다.
- 약 개수는 `+/-`뿐 아니라 직접 입력 숫자 키패드로도 입력한다.

**상태: 반영 확인**

### 5-5. 5단계 신체활동

- 신체활동 안내는 상단에 고정하고, 원 설문 문장을 유지하되 핵심 단어를 굵게·밑줄로 강조한다.
- 세부 활동 예시는 태그로 표시한다.
- 강도별 흐름은 `1/4~4/4`로 표시한다.
- 일수는 0~7일의 큰 칩으로 단번에 선택한다.
- `0일(안 함)`이면 시간·분 상세 입력을 생략하고 다음 문항으로 이어진다.
- 1일 이상이면 시간·분 입력과 키패드가 동적으로 나타난다.
- 시간·분은 각각 직접 입력할 수 있고, 입력 대상 탭의 상태가 분명해야 한다.

**상태: 반영 확인 / 후속 점검**

- 일수 기반 분기, 시간·분 키패드, 활동별 안내 카드가 구현되어 있다.
- 실제 설문 원문과 제공 HTML의 문항 문구·순서가 모두 일치하는지 회귀 비교가 필요하다.

### 5-6. 6단계 기능적 이동성(TUG)

- 타이머 시작·정지·초기화 흐름을 제공한다.
- 측정값은 초 단위로 직접 입력할 수 있으며, 숫자 입력 영역은 가운데 정렬한다.
- 이전 문항으로 이동해도 이미 잰 시간 또는 직접 입력한 값이 유지되어야 한다.

**상태: 반영 확인 / 후속 점검**

- 타이머와 초 단위 키패드가 존재한다.
- 브라우저 백/앞으로 이동, 페이지 새로고침 후 값 유지 범위는 제품 정책과 함께 확인한다.

### 5-7. 7단계 마음건강

- SGDS-K 문항은 한 화면 한 질문으로 표시한다.
- 짧은 선택 문항은 화면 중간에 균형 있게 놓고, 버튼이 하단 내비게이션에 가리지 않게 한다.

**상태: 반영 확인 / 후속 점검**

## 6. 노쇠 예측 설문 결과

### 6-1. 결과 요약

- 상단에는 결과 상태(정상/위험), 기준선, 현재 위험도, 짧은 권고 문구를 둔다.
- “정상” 등 상태는 색상뿐 아니라 텍스트와 아이콘으로 구분한다.
- 기준선과 현재 수치를 노쇠 위험 바 위에서 쉽게 비교할 수 있게 한다.
- 결과 화면의 장황한 설명 문구는 제거하고, 제목·수치·권고의 위계를 우선한다.

**상태: 반영 확인**

### 6-2. 영역 요약

- 신체·정서 영역의 기여 비중을 한눈에 읽을 수 있는 막대 구성으로 표시한다.
- 숫자 불릿은 제거하고, “설문에 따른 노쇠 위험 결과”, “영역 요약 및 항목별 영향 요인” 제목은 카드 내부 콘텐츠 정렬에 맞춘다.
- 각 결과 섹션은 흰색 중심의 카드와 도움말과 같은 연한 1px 외곽선으로 구분한다.
- 과도한 회색 배경·강한 그림자·두꺼운 실선은 피한다.

**상태: 부분 반영 / 후속 점검**

- 결과 카드·영역 비율·항목 영향도 UI는 구현되어 있다.
- 최신 FigJam 시안의 정확한 수치(예: 정상 0.1%, 신체 26%, 정서 74%)를 기본 데모 데이터로 고정할지, 실제 답변으로 계산할지는 결정이 필요하다.

### 6-3. 항목별 영향 요인

- 보행기능, 우울감, 나이(참고), 복용약물, 체중, 활동량을 보호/위험/참고 상태로 표시한다.
- 도움 됨과 위험을 키움의 방향성을 한 화면에서 읽을 수 있어야 한다.
- 각 항목은 큰 레이블, 상태 텍스트, 막대, 영향도 수치로 구성한다.

**상태: 부분 반영 / 결정 필요**

- UI와 항목 렌더링은 구현되어 있다.
- 실제 의학적 모델의 변수별 영향도·부호·색상 기준은 연구팀/도메인 검토 후 확정해야 한다.

### 6-4. 저장·공유·상담 진입

- 결과 하단에는 PDF 저장, 이미지 저장, 공유하기, 결과 링크 복사만 노출한다.
- “설문 원자료 CSV”는 결과 화면에서 삭제한다.
- 상담 진입 카드에는 부비 캐릭터, 한 줄 제목·설명, 상담 시작 버튼을 배치한다.
- 상담 카드와 저장/공유 카드 높이는 같은 행에서 균형 있게 맞춘다.

**상태: 반영 확인 / 결정 필요**

- 결과 화면의 메뉴는 PDF 저장·이미지 저장·공유하기·결과 링크 복사로 정리되어 있다.
- 실제 PDF/이미지 생성, 공유 URL의 접근 권한과 만료, 저장 범위는 백엔드 정책이 필요하다.

## 7. 건강정보 배움터

- 카드 제목·본문은 제공된 설문/건강정보 HTML의 문구를 그대로 반영한다.
- 우측 상단 “학습 기록 내려받기”는 삭제한다.
- 일러스트는 부엉이를 제외하고 능동적·주도적 시니어 스타일로 통일한다.
- 카드 일러스트에는 스티커처럼 분리된 그림자가 아니라 이미지와 자연스럽게 결합된 그림자를 사용한다.
- 데스크톱도 태블릿과 동일한 카드 정보 구조를 사용하며, 부족한 높이는 스크롤로 해결한다.

**상태: 반영 확인 / 후속 점검**

- 카드 문구와 학습 기록 다운로드 제거가 현재 소스에서 확인된다.
- 외부 이미지 저작권·출처·라이선스 기록은 별도 자산 관리 문서가 필요하다.

## 9. 1:1 상담

- 결과 전에는 상담을 비활성화하거나 결과 확인 후 이용 가능하다는 상태를 명확히 보여준다.
- 결과 후에는 “부비와 함께하는 1:1 상담” 카드에서 상담 시작을 제공한다.
- 채팅 화면의 “대화 종료하기”는 링크처럼 보이지 않고 명확한 버튼이어야 한다.
- 메시지 입력창은 최소 세 줄이 보이도록 높이를 확보한다.
- “상담 원자료” 항목은 상담 화면에서 삭제한다.

**상태: 반영 확인 / 결정 필요**

- UI 상태, 종료 버튼, 3줄 입력창은 구현되어 있다.
- 생성형 AI 상담의 실제 연결, 대화 저장, 의료 고지, 위기 대응, 개인정보 보존 기간은 별도 제품·법무 결정을 거쳐야 한다.

## 10. 일러스트·브랜드 자산

- 부엉이 BUVI는 브랜드 캐릭터로 유지한다.
- 사람 일러스트는 수동적 환자 이미지 대신 걷기·운동·기기 사용·소통하는 능동적 시니어를 사용한다.
- 이미지가 작은 카드 안에서 잘리지 않도록 컨테이너 크기와 `object-fit`을 화면별로 조정한다.
- 로고는 캐릭터+“어르신 건강 지킴이 '부비'” 텍스트 구성을 사용하며, 캐릭터와 텍스트 사이의 세로선은 제거한다.

**상태: 반영 확인 / 후속 점검**

- 주요 캐릭터/일러스트 교체와 로고 카피가 반영되어 있다.
- 신규 외부 자산 교체 시 파일명 버전, 원본 출처, 사용 범위를 자산 목록에 남긴다.
